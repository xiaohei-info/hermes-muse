# Hermes Muse

[English](README.md) · [设计文档](docs/DESIGN.md) · [验收清单](docs/ACCEPTANCE.md)

这个项目受 [Meta Muse](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/) 的主动交互能力启发。我想把类似的体验带到 [Hermes](https://github.com/NousResearch/hermes-agent)：聊天里说过的目标能继续跟进，后台发现有价值的新进展时会来告诉你，事情结束后也知道停下来。

随口提过的兴趣，过一阵子没再提就该退场；明确约好的提醒，要按约定执行。说了“已经办好了”，助手就该停止追踪。它突然发来一条消息，我也应该能问清楚为什么。

Hermes 已经有记忆、Skill、Cron 和后台子任务。这个插件把它们串起来，希望逐步做出一个像 Muse 那样能主动跟进事情的 personal agent。安装后会加上 1 个 Skill、4 个固定 Cron、5 份提示词和一个状态工具，沿用你已有的模型、记忆和服务连接。Hindsight、Obsidian 或任何聊天平台都不是必装项。

代码和提示词由本项目独立编写，与 Meta 或 Muse 没有隶属关系，目前也没有实现 Muse 的全部功能。

## 安装

```sh
hermes plugins install xiaohei-info/hermes-muse --enable
```

需要 Hermes 0.21.5 或具备相关插件接口的更新版本，测试基线见[验收清单](docs/ACCEPTANCE.md)。安装时遵循 Hermes 原有的来源与安全检查，插件本身不需要额外的 Python 依赖或账号凭据。

Hermes 第一次实际加载插件时会自动初始化：建立当前 profile 的工作区、注册 Skill 和提示词、创建四个 Cron，并把任务 ID 和文件归属写进 `muse/install.json`。宿主正在运行时可以通过重载完成，否则等下次启动。整个插件一起安装，不需要选功能、指定路径或再执行初始化命令；已有工作区文档会保留。

安装后开一个新会话，才能使用新增的系统提示词段。旧会话的提示词缓存保持原样。后台工作还需要 Hermes 调度器在线，且当前模型可用。

安装不会改写 Hermes 核心、`SOUL.md`、原生 `USER.md`/`MEMORY.md`、项目 `AGENTS.md` 或全局系统提示词。使用中需要保存新事实时，助手会调用你原有的记忆工具。

## 怎么用

照常和 Hermes 聊天，例如：

- “这个月我要选一辆自行车，预算……”
- “最近对城市园艺有点兴趣。”
- “帮我等这封邮件的回复，检查到周五就行。”
- “为什么提醒我这个？”“这次不用。”
- “已经买好了，可以停止关注了。”
- “看看我的 Feed 里有哪些园艺文章。”

随口提到的兴趣默认保留 14 天。你之后再次提起，可以续期；助手自己的研究、旧记忆和新发现的新闻都不能替你续期。正式目标有进度、完成条件和复核时间；没有截止日期的目标会在 30 天后进入研究复核，但不会因此取消明确约定的提醒。

目标完成或取消后，关联监控会停止，相关 Ideas 也会退役。已经做完但还没告诉你的最终结果，仍然需要交付。“已处理”“这次不要”“稍后提醒”和“以后别提这个主题”会分别处理，不把一次拒绝当成永久偏好。

想知道它在关注什么，直接问“现在 Hermes Muse 记录了哪些目标、兴趣和提醒”。日常使用不需要记工具参数。

## 后台在做什么

| 任务 | 默认频率 | 做什么 |
| --- | --- | --- |
| muse-proactive-watch | 每 30 分钟 | 找相关变化，核实证据，判断是否值得提醒 |
| muse-memory-upkeep | 每小时 | 有新增用户信息时整理事实、人物和群组资料 |
| muse-nightly-review | 每天 03:20 | 回顾交流，更新对齐理解，研究部分目标，复盘 Ideas 和技能 |
| muse-feed-pulse | 每小时 | 有新材料值得写时，生成带来源的文章 |

任务继承 Hermes 的时区和模型。没有工作时，前置脚本会在调用模型前跳过；实际研究和写文章仍会产生你所用模型、工具的正常费用。Feed 每小时检查一次，不代表每小时必须写一篇。

一次较长的交流结束后，如果安静了一段时间，插件可以提前唤醒已有的记忆维护任务。新消息会重新计时，每天最多触发三次。它能判断的是 Hermes 里的活动，不会据此断言你在其他地方也有空。

明确约定的提醒、目标监控和消息交付会按需创建附属 Cron，任务 ID 都会登记，方便结束和卸载时清理。临时兴趣不会自动变成永久监控。

## 提醒、Feed 和研究

准备好的提醒在输出前还会检查一次：是否过期、目标或兴趣是否仍有效、你有没有拒绝这个主题、当前时段和次数是否允许。同一事件标识不能被两个后台任务各自重复入队；不同来源说的是不是同一件事，仍需要助手判断。

消息发回已记录的来源会话，或唯一明确配置的默认通知渠道。没有可用渠道就保留到下次本地查看。原主会话允许后台唤醒时，插件可以把证据交回去重新判断；未允许时使用原生 Cron 投递，不自行开启这个权限。

准备完成、已入队、发送中和实际投递结果分开记录。超时或部分发送造成的未知结果不会自动重发。渠道报告发送成功，也不等于手机一定弹出了通知，或你已经读过。

Feed 文章静默保存在本地。你可以通过聊天查看、搜索、排序、讨论和删除，也可以修改之后的选题偏好。只有明确反馈才用于判断喜好，打开文章本身不算喜欢。当前版本没有独立的原生 Feed 页面。

独立研究问题交给 Hermes 子任务，每批最多三个。助手用 `research_status` 收集结果并推进下一批，主对话可以继续。缺少结果会说明，失败的研究项最多重试一次；宿主重启后无法确认状态的任务不会擅自重新创建。

浏览器保留现场后恢复、电话和设备服务暂时不在本版范围内，具体能做什么仍取决于你自己的 Hermes。

## 文件和记忆

文件放在当前 profile 的 `HERMES_HOME` 下，默认通常是 `~/.hermes`：

- `plugins/hermes-muse/`：代码、Skill、五份提示词和通用模板。
- `muse/install.json`：固定及附属任务 ID、入口脚本归属；卸载后保留。
- `muse/state.db`：兴趣有效期、提醒状态、次数和 Feed 索引等运行记录。
- `muse/AGENTS.md`、`TOOLS.md`、`PROACTIVE_PREFERENCES.md`：工作约定、实际信息源、提醒和 Feed 偏好。
- `muse/memory/`：每日整理、人物和群组资料。
- `muse/dreams/`：反思记录，以及 `alignment/derived/ALIGNMENT_SYNTHESIS.md`。
- `muse/workspace/goals/<目标>/`：`GOAL.md`、交付文件 `files/` 和研究材料 `hidden_files/`。
- `muse/workspace/your_files/feed/`：文章。
- `scripts/hermes-muse-*.py`：Hermes Cron 要求的入口，实际逻辑留在插件里。

`memory`、`dreams` 和目标目录借鉴 Muse 的组织方式；安装记录、SQLite 状态、Feed 落盘和原生记忆路径是为 Hermes 做的适配。有内容时才创建相应笔记和目标文件，初次安装不会填入虚构的个人资料。

会话钩子会保存较短的用户原话片段，供后续维护处理。未处理的片段保留到维护成功，已处理历史保留有限数量；长期事实仍交给现有记忆服务。插件不收集遥测，也不会把个人助理状态带入群聊。具体数据范围见 [SECURITY.md](SECURITY.md)。

要求“忘记”某件事时，助手会先停止相关工作，删除插件记录及已索引的衍生内容，再检查其他笔记和可用记忆工具。历史聊天、备份或外部索引无法确认删除时，需要如实说明。

## 卸载

```sh
hermes plugins remove hermes-muse
```

然后告诉现有 Hermes 助手：

> Hermes Muse 已卸载。读取当前 profile 的 muse/install.json，只暂停并删除其中登记的 Cron，包括目标监控和交付任务；检查正在执行的任务；清理登记的 scripts/hermes-muse-* 入口。保留我的目标、文章、笔记和记忆。还有任务在运行或结果未知的话，告诉我。

Hermes 的原生 remove 不能保证调用插件的 Cron 清理回调，所以需要这一步。卸载或停用后的遗留入口会静默；已经在运行的任务仍需检查。

再次安装会保留数据并修复缺失任务，普通重载会尊重你主动暂停的任务。只有也想删除数据时，才清理留下的 `muse/` 目录。

## 开发和验收

```sh
python -m unittest discover -s tests -v
# 在 Hermes 环境中：
python tests/native_smoke.py
hermes plugins validate . --json
```

测试使用临时 profile，不通过你的账号发送消息。实际模型和渠道的表现，需要按[验收清单](docs/ACCEPTANCE.md)检查；自动化测试不能替代这些体验。文件和任务的分工见[设计文档](docs/DESIGN.md)。

安装和更新都走 Hermes 官方命令，插件没有自己的更新器。GitHub 版本可以直接安装，[官方目录申请](https://github.com/NousResearch/hermes-agent/pull/134976)正在等待审核。
